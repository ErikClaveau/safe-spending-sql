# ADR-009: The demo

> 🇪🇸 Español: [../es/adr/0009-demo.md](../es/adr/0009-demo.md)

**Status:** Accepted
**Date:** 2026-10-29
**Decides:** Erik Claveau
**Related:** ADR-002 (isolation via RLS only), ADR-007 (tracing), ADR-010 (ambiguity)

## Context

The project needs something a reader can try or watch in two or three minutes (Definition of Done, plan §15). Its pitch is not "a chatbot over bank data" but *isolation you can break and numbers you can trace*, so the demo has to make those two things visible, not only answer questions.

The assistant is a Python library today: `Assistant.ask(user_id, question)` returns an `AssistantResult` with every stage (SQL, validation, rows, corrections, answer, number check, cost, latency). There is no API and no authentication. The plan lists three options: Streamlit, a plain HTML page, or only an API plus a video.

## Decision

**A Streamlit app that calls `Assistant.ask` in-process. No FastAPI in this iteration.**

- **Who is asking.** A sidebar selector picks one of the synthetic users. It stands in for the auth layer: `user_id` comes from that widget, never from the question text (the invariant of ADR-002). The app says so on screen.
- **What it shows per question.** The answer text; the generated SQL; the rows; the validator verdict; how many corrections were needed; cost and latency by stage. The numbers in the answer are the ones the verifier already traced to the result, and the page shows that.
- **A "try to break it" panel.** Preloaded questions from the adversarial set (ask for another user's data; an injection trap in a transfer concept) run as one user, so the viewer sees the validator or RLS stop it and the answer ignore the planted text. This is the part that distinguishes the project; the ordinary Q&A is the setup for it.
- **Frozen "today".** The app uses `FixedClock` (2026-09-15), as ADR-008 requires, so "last month" means the same thing as in the evals.
- **Database.** The app connects as `app_reader` to a development database loaded by `safe-spending-load`. It never uses the golden reference database and never connects as a role that bypasses RLS.
- **Shipping.** `docker compose up` starts Postgres, loads the dataset and starts the app. The `ANTHROPIC_API_KEY` is the only secret the reader supplies. A 2-3 minute video of the same flow is recorded as a fallback for readers without a key.

## Options considered

| Option | Effort | Impact | Problem |
|---|---|---|---|
| **Streamlit, in-process** | Low: a single Python file over the existing `Assistant` | High: interactive, shows SQL and rows, runs from one command | Not a real client/server split; not how a bank would deploy it |
| Plain HTML + FastAPI | Medium to high: the API, auth stub, CORS, a front end | Medium: looks more like a product | Spends the last week on plumbing that the evals do not measure; the API would have no auth to show |
| Only API + video | Low | Low: nobody can try it, and a video cannot be checked | A reader cannot test the isolation claim, which is the claim |

## Consequences

**Easier**
- The demo exercises exactly the code the evals measure, so there is no second path to keep correct.
- The isolation claim is something the reader can try, not only read.
- No new service to secure or document.

**Harder**
- The user selector is a stand-in for authentication, not authentication. The README must say this plainly so nobody reads the demo as a deployment pattern.
- `build_assistant` lives in `evals/harness/` today. The app needs the same wiring with different settings (development database, `app_reader`, no Inspect). That wiring should move out of the evals package into a shared factory, with the evals and the app both calling it, instead of the app importing from the evals.
- Streamlit reruns the script on each interaction, so the assistant and its connections must be created once and cached.
- Each question costs real API money; the app should show the cost per question and has no rate limit of its own.

**To revisit**
- A FastAPI service with real authentication, if the project moves beyond a portfolio piece. The `Assistant` already has the shape of its core.
- Conversation state, which ADR-010 already lists as the condition for `clarify` to keep the original question.
