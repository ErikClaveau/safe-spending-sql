# ADR-009: La demo

> 🇬🇧 English: [../../adr/0009-demo.md](../../adr/0009-demo.md)

**Estado:** Aceptado
**Fecha:** 2026-10-29
**Decide:** Erik Claveau
**Relacionados:** ADR-002 (aislamiento solo con RLS), ADR-007 (trazas), ADR-010 (ambigüedad)

## Contexto

El proyecto necesita algo que un lector pueda probar o ver en dos o tres minutos (definición de hecho, plan §15). Su propuesta no es «un chatbot sobre datos bancarios» sino *un aislamiento que se puede intentar romper y números que se pueden rastrear*, así que la demo tiene que hacer visibles esas dos cosas, no solo responder preguntas.

Hoy el asistente es una biblioteca de Python: `Assistant.ask(user_id, question)` devuelve un `AssistantResult` con todas las etapas (SQL, validación, filas, correcciones, respuesta, comprobación numérica, coste, latencia). No hay API ni autenticación. El plan enumera tres opciones: Streamlit, una página HTML simple, o solo una API más un vídeo.

## Decisión

**Una app de Streamlit que llama a `Assistant.ask` en proceso. Sin FastAPI en esta iteración.**

- **Quién pregunta.** Un selector en la barra lateral elige uno de los usuarios sintéticos. Sustituye a la capa de autenticación: el `user_id` sale de ese widget, nunca del texto de la pregunta (el invariante del ADR-002). La app lo dice en pantalla.
- **Qué muestra por pregunta.** El texto de la respuesta; el SQL generado; las filas; el veredicto del validador; cuántas correcciones hicieron falta; coste y latencia por etapa. Los números de la respuesta son los que el verificador ya rastreó hasta el resultado, y la página lo muestra.
- **Un panel «intenta romperlo».** Preguntas del set adversarial precargadas se ejecutan como un usuario, de modo que el espectador ve cómo el validador o RLS lo frenan y la respuesta ignora el texto plantado. Esto es lo que distingue al proyecto; las preguntas normales son el preparativo.
- **«Hoy» congelado.** La app usa `FixedClock` (2026-09-15), como exige el ADR-008, de modo que «el mes pasado» significa lo mismo que en las evals.
- **Base de datos.** La app se conecta como `app_reader` a una base de desarrollo cargada con `safe-spending-load`. Nunca usa la base de referencia del golden set ni se conecta con un rol que se salte RLS.
- **Entrega.** `docker compose up` levanta Postgres, carga el dataset y arranca la app. La `ANTHROPIC_API_KEY` es el único secreto que aporta el lector. Se graba un vídeo de 2-3 minutos del mismo flujo como alternativa para quien no tenga clave.

## Opciones consideradas

| Opción | Esfuerzo | Impacto | Problema |
|---|---|---|---|
| **Streamlit, en proceso** | Bajo: un único fichero de Python sobre el `Assistant` existente | Alto: interactivo, muestra SQL y filas, se ejecuta con un comando | No es una separación cliente/servidor real; no es como lo desplegaría un banco |
| HTML simple + FastAPI | Medio-alto: la API, un stub de autenticación, CORS, un front | Medio: parece más un producto | Gasta la última semana en fontanería que las evals no miden; la API no tendría autenticación que mostrar |
| Solo API + vídeo | Bajo | Bajo: nadie puede probarlo y un vídeo no se puede comprobar | El lector no puede probar la afirmación de aislamiento, que es la afirmación |

## Consecuencias

**Más fácil**
- La demo ejercita exactamente el código que miden las evals, así que no hay un segundo camino que mantener correcto.
- La afirmación de aislamiento es algo que el lector puede probar, no solo leer.
- Ningún servicio nuevo que asegurar o documentar.

**Más difícil**
- El selector de usuario sustituye a la autenticación, no es autenticación. El README debe decirlo con claridad para que nadie lea la demo como un patrón de despliegue.
- `build_assistant` vive hoy en `evals/harness/`. La app necesita el mismo montaje con otros ajustes (base de desarrollo, `app_reader`, sin Inspect). Ese montaje debe salir del paquete de evals a una factoría compartida que usen las evals y la app, en lugar de que la app importe de las evals.
- Streamlit vuelve a ejecutar el script en cada interacción, así que el asistente y sus conexiones deben crearse una vez y guardarse en caché.
- Cada pregunta cuesta dinero real de API; la app debería mostrar el coste por pregunta y no tiene límite propio.

**A revisar**
- Un servicio FastAPI con autenticación real, si el proyecto va más allá de una pieza de portfolio. El `Assistant` ya tiene la forma de su núcleo.
- El estado de conversación, que el ADR-010 ya enumera como condición para que `clarify` conserve la pregunta original.
